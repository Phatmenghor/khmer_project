## 2. Existing Coding Patterns & Conventions

### Patterns Successfully Followed
1. **Feature-by-Package Isolation:** Features encapsulate their own controllers, services, models, repositories, and DTOs within distinct package namespaces.
2. **Unified Response Envelope:** Endpoints return standard `ApiResponse<T>` wrappers with standard status codes, timestamps, and request trace IDs.
3. **Automated DTO Mapping:** MapStruct mappers with `componentModel = "spring"` decouple persistence models from API contracts.
4. **Contextual Correlation:** `RequestIdFilter` populates MDC (`traceId`, `userId`, `userIdentifier`) across log messages.
5. **Fail-Fast Configuration Validation:** Security configurations check JWT secret key length at boot time using `@PostConstruct`.

### Anti-Patterns & Violations Identified
1. **ThreadLocal Lifecycle Mismanagement:** `JWTAuthenticationFilter` binds user context to `ThreadLocal` without a guaranteed `finally { remove(); }` cleanup block, creating thread contamination across Tomcat worker threads.
2. **Repeated DB Security Lookup:** `SecurityUtils.getCurrentUser()` extracts the JWT token from `RequestContextHolder` and queries PostgreSQL `userRepository.findByIdAndIsDeletedFalse(...)` on every call (up to 5+ DB lookups per request).
3. **Direct Entity & Repository Exposure in Controllers:** `ApiKeyController` in `resource-storage-service` invokes `ApiKeyRepository` directly inside controller methods without service abstraction.
4. **Blocking OS Process Execution in Request Threads:** `StorageServiceImpl` spawns synchronous `ProcessBuilder("ffmpeg", ...)` execution directly inside HTTP request threads for unsupported image format conversions.
5. **Database Schema Unsafe in Production:** `application-prod.yaml` sets `hibernate.ddl-auto: update` while Flyway migration scripts are completely absent.

## 4. Inconsistencies & Cross-Project Deficiencies

1. **Service Abstraction Inconsistency:**
   * `menu-scanner-backend` strictly enforces Controller -> Service -> Repository layer pattern.
   * `resource-storage-service` violates this in `ApiKeyController`, bypassing the service layer and invoking `ApiKeyRepository` directly.
2. **Java & Compiler Configuration Mismatches:**
   * Both projects declare `<java.version>17</java.version>` in `pom.xml` properties while instructing `maven-compiler-plugin` to compile targeting Java 21 bytecode.
3. **MapStruct Processor Duplication:**
   * `menu-scanner-backend` declares `mapstruct-processor` as a provided dependency AND inside `maven-compiler-plugin` annotation processor paths.
   * `resource-storage-service` does not use MapStruct at all, performing manual DTO transfers.
4. **Database Migration Strategy:**
   * `menu-scanner-backend` includes Flyway dependencies but disables them in configuration while leaving production on Hibernate `ddl-auto: update`.
   * `resource-storage-service` relies entirely on Hibernate `ddl-auto: update` without Flyway dependencies.

## 6. Prioritized Refactoring Plan (Phase 1 – Phase 8)

### PHASE 1 — Critical / Security
* **Fix `ThreadLocal` Leak:** Modify `JWTAuthenticationFilter.java` to clear `AUTHENTICATED_USER` and MDC in a `finally` block.
* **Purge Hardcoded Secrets:** Remove default secrets from `application-prod.yaml`, `application-dev.yaml`, and `application-local.yaml`. Enforce environment variable injection.
* **Hash Storage API Keys:** Update `ApiKeyUtil.java`, `ApiKeyController.java`, and `ApiKey.java` to hash keys using SHA-256 before database insertion.
* **Disable Production DDL-Auto:** Change `spring.jpa.hibernate.ddl-auto` to `validate` in `application-prod.yaml`.

### PHASE 2 — Bugs / Correctness
* **Fix Security Context Query Amplification:** Refactor `SecurityUtils.java` and `JWTAuthenticationFilter.java` to cache user identity in request scope / SecurityContext.
* **Fix Validation Exception Handling:** Add `MethodArgumentNotValidException` handler to `GlobalExceptionHandler.java` in `resource-storage-service`.
* **Add Batch Payload Validation:** Annotate `createUserBatch` and `createRoleBatch` parameters with `@Valid List<@Valid DTO>`.

### PHASE 3 — Architecture / Design
* **Create `ApiKeyService`:** Extract repository calls out of `ApiKeyController.java` into a dedicated `ApiKeyServiceImpl.java`.
* **Asynchronous Media Processing:** Refactor `StorageServiceImpl.java` to isolate OS ffmpeg process execution into a separate component with worker thread pools.
* **Standardize Java Target:** Align `<java.version>` to `21` in both `pom.xml` files.

### PHASE 4 — Code Quality
* **Consolidate Enums:** Merge `com.emenu.enums.common.StockStatus` and `com.emenu.enums.product.StockStatus` into a single canonical enum.
* **Streamline Exceptions:** Consolidate redundant exception classes (`NotFoundException`, `UserNotFoundException`) into `BusinessException`.
* **Clean Root Artifacts:** Remove `package-lock.json` and root script files from backend repository.

### PHASE 5 — Duplication / Standardization
* **Standardize Dependency Declarations:** Move `openpdf` version to `<properties>` in backend `pom.xml`.
* **Clean Unused Dependencies:** Remove unused TwelveMonkeys ImageIO plugins from `resource-storage-service/pom.xml`.

### PHASE 6 — Performance & Database
* **Fix JPA Fetch Strategy:** Change `FetchType.EAGER` to `FetchType.LAZY` on `Attendance.java` `checkIns`.
* **Add Foreign Key Indexes:** Add `@Table(indexes = ...)` on FK columns across entity models.

### PHASE 7 — Testing
* **Create Test Suites:** Create `src/test/java` in `resource-storage-service`. Add unit tests for `StorageServiceImpl` and `ApiKeyAuthFilter`.
* **Backend Unit & Integration Tests:** Implement JUnit 5 + Mockito tests for `AuthServiceImpl`, `OrderServiceImpl`, and API endpoints using Testcontainers.

### PHASE 8 — Final Cleanup
* Enable Flyway migrations (`spring.flyway.enabled: true`) and add initial schema SQL script (`V1__init_schema.sql`).
* Format code according to project conventions and verify clean build.
